# Bounded numeric interpretation experiment

Date: 2026-10-20. Source lexicon: OEWN 2024.

This tests exact execution of five manually interpreted numeric senses. It is
not evidence of intrinsic grounding, discovery of semantic primitives, learning,
general English parsing, or transfer of meaning across the full dictionary.

## What runs

`data/numeric-senses.json` retains verbatim dictionary glosses, sense IDs and source
synsets. All five records were independently compared with Q's existing local
`C:/Users/Q/.wn_data/wn.db`, opened with SQLite `mode=ro`: 5/5 matched exactly.
The fixture supplies `SenseRecord`s; its `unclassified` lexicality is not an
admission-policy verdict. A fresh run needs only the fixture and standard library,
not that local database or a download.

`src/meanings/numeric_experiment.py:AUTHORED` contains the separate, human-authored
expressions. Odd explicitly substitutes a reference to the numeric even sense for
"divisible by two"; nonnegative references the numeric positive sense. The
interpreter does not translate the English glosses automatically. Primitive
comparison, equality and divisibility operations are programmer-supplied meanings.

Evaluation uses sense IDs, never an IC-wide OR or a lemma fallback. Conjunction,
disjunction and negation follow strong Kleene truth tables. Missing bindings,
missing or cyclic sense references, and observations outside the integer domain
return unknown (`null` in JSON). Booleans are excluded from the integer domain.

## Reproduction

From the repository root in PowerShell, with Python 3.12 or later:

```powershell
python -B -m pytest -p no:cacheprovider -q tests/test_interpretation.py
$env:PYTHONPATH = 'src'
python -B -m meanings.numeric_experiment
```

The runner writes JSON to stdout and exits unsuccessfully if the correct arm has
any reference error or unknown judgment. The committed JSON is its captured output.

## Results

Focused test output: `21 passed in 0.76s`.

| Split / arm | Integer observations per sense | Judgments | Errors | Unknown |
| --- | ---: | ---: | ---: | ---: |
| Development / correct | 21 | 105 | 0 | 0 |
| Development / wrong binding | 21 | 105 | 60 | 0 |
| Development / operator erasure | 21 | 105 | 32 | 0 |
| Held-out / correct | 1,980 | 9,900 | 0 | 0 |
| Held-out / wrong binding | 1,980 | 9,900 | 5,940 | 0 |
| Held-out / operator erasure | 1,980 | 9,900 | 2,970 | 0 |

Development is -10..10. Held-out is -1000..-11 and 11..1000, with no overlap.
No fitting or tuning occurs; these are held-out referents, not learned grammar.
Arithmetic references are enumerated sets: multiples of two are generated by
multiplication, and sign extensions by integer ranges, independently of the
predicate bindings used by the interpreter.

Wrong binding swaps greater-than and less-than operations while keeping source
sense IDs, expressions, observations and reference sets fixed. It causes 60% error
on the held-out judgments. Operator erasure removes NOT and turns OR into AND,
retaining references and primitive leaves; it causes 30% error. This conjunction
control is not a replay of the published dependency-graph tokenizer/resolver.

The result establishes correct execution and sensitivity to these controlled
changes in a declared computational domain. It does not establish grounding supply
or the adequacy, minimality or dictionary-scale coverage of an English basis.
No physical observations were acquired; no tokenizer or graph pipeline changed.
