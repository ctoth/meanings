## 1. The current architecture

### 1.1 The OEWN → graph → kernel → exports pipeline

The repo is one pipeline with three stages, all under `src/meanings/`:

**Stage A — build a definition digraph from a WordNet lexicon.** `wordnet_pipeline.py` exposes three builders, selected by `--graph-type`:

- `build_lemma_graph` (`graph-type lemma`, `wordnet_pipeline.py:169`) — node = `lemma::pos`, edge `u → v` = "lemma `u` occurs (after normalization/tokenization) in a definition of `v`". Coarse: collapses senses, uses lemma normalization from `normalize.py`.
- `build_synset_graph` (`graph-type sense`, `wordnet_pipeline.py:195`) — node = synset id, edge = "a word in synset `u` occurs in the gloss of synset `v`", with a representative-sense resolution step (`resolution_stats`). Labelled by `synset_label`. README calls this "experimental".
- `build_paper_wordnet_graph` (`graph-type paper-wordnet`, `wordnet_pipeline.py:296`) — the "paper-faithful" reconstruction of the Vincent-Lamarre / Massé build, returning a `LexicalGraphBuild` with `graph_type="paper_wordnet"`. **This is the measuring stick** (README "Status"): 160,010 nodes / 677,823 edges on `oewn:2024`. Build time ~83–93 s (dominated by `wn` access).

The edge convention is **uniform across the repo and the spectral/argumentation work**: `u → v` means "u occurs in the definition (gloss) of v" — *defining → defined / forward* (`spectral_analysis.py` docstring; `argumentation_bridge.py` docstring). Note this is *not* a sense-disambiguated graph: a gloss occurrence resolves to a lemma/representative-synset, not to the intended sense — the central limitation §1.3 / §3.4 turn on.

**Stage B — `analyze_kernel`** (`graph_analysis.py:169`, returning `KernelAnalysis` at `:13`). It does, in order:

1. `compute_kernel` (`graph_analysis.py:84`) — iterated leaf-stripping: repeatedly delete nodes with no surviving outgoing definition edge (a word whose entire definiens is already grounded) until a fixpoint. **The self-loop fix this round** (commit `7d12e64`): a self-loop `u → u` (a word in its own gloss) now counts as a cycle, so such a node stays in the Kernel; previously it was peeled out. This is the *only* behavioural change the fix makes.
2. SCC decomposition of the Kernel (`strongly_connected_components`, `graph_analysis.py:43` / `minset.py:55`) → `kernel_sccs`; the source SCCs (no incoming edges in the condensation) → `source_sccs`; `core_nodes` = union of source SCCs (`--core-policy source-union`) or the largest SCC (`largest-scc`); `satellite_nodes` = Kernel − Core.
3. The **seed / MinSet solver** — `solve_minset(nodes, adjacency, method)` from `minset.py:391`, dispatching to one of three feedback-vertex-set heuristics: `bounded-scc` (`bounded_cycle_hitting_set`, `minset.py:168` — 8-pass cap, one FVS pick per cyclic SCC per pass, `choose_feedback_vertex` picks the max `internal_out + internal_in` node); `exact-small-greedy` (`exact_small_greedy_cycle_hitting_set`, `:264` — solves SCCs ≤ 12 exactly by brute combinations, greedy on larger, loops to completion); `exact-cutting` (`exact_cutting_cycle_hitting_set`, `:334` — one pass, lazy-cycle exact solve for SCCs ≤ 18). All return a `MinSetResult` (`minset.py:22`) carrying per-SCC `SccMinSetResult` metadata and `residual_cyclic_scc_count` — if that residual is non-zero the Kernel isn't fully cracked so `analyze_kernel` skips the layer map.
4. `compute_layer_map` (`graph_analysis.py:132`) — once the seed makes the residual acyclic, distance-from-seed layers; `layer_histogram` + `layer_by_node`.

**Stage C — exports.** `wordnet_pipeline.py` renders Markdown + JSON reports (`render_paper_wordnet_markdown_report` `:477`, `write_paper_wordnet_json_summary` `:574`, plus synset variants). `annotations.py` overlays psycholinguistic CSVs onto layers. And — new this round — a **kernel-wordlist exporter** (commits `b9d2caf`, `185b04a`, `b4ea845`, `1948501`, `d3c144a`: "Add kernel wordlist exporter", "Export human seed word lists", "Export Up-Goer kernel wordlists") that projects the graph seed down to a human word list — the Up-Goer surface Q has been shipping. *(I did not read the exporter module itself — flag: I'm describing it from commit messages and `notes/upgoer-identity-clusters.md`, not from source.)*

`spectral_analysis.py` is a parallel read-only analysis surface (Perron / PageRank over the same `build_paper_wordnet_graph` adjacency), not part of the pipeline; `scripts/spectral_report.py` drives it.

### 1.2 The `meanings` ↔ `../argumentation` boundary

There are two repos and one bridge module.

- **`../argumentation`** (`formal-argumentation`, pinned in `pyproject.toml` as `formal-argumentation @ git+https://github.com/ctoth/argumentation@<commit>` — see §2 for the live pin): ~20.5k lines, zero core deps. Provides the *semantics*: Dung AAFs (`argumentation.dung.ArgumentationFramework` = `(frozenset nodes, frozenset edges)`, grounded/complete/preferred/stable/etc.), ASPIC+, ABA/ABA+, **ADFs with typed acceptance-condition ASTs**, **bipolar AFs** (`argumentation.bipolar.BipolarArgumentationFramework`, a second `supports` edge relation), value-based AFs, SETAFs, claim-augmented AFs, partial/incomplete AFs, **AF revision / dynamics / minimal-change enforcement**, probabilistic AFs, **gradual/ranking semantics** (`argumentation.ranking`: h-categorizer, burden, Potyka, DF-QuAD, Shapley), weighted AFs, SAT/ASP/datalog encodings (`argumentation.af_sat` — z3 backend), ICCMA interop. **It ships no graph-theory toolbox**: one private Tarjan SCC for cf2/stage2; no FVS, no cycle enumeration, no public SCC API. It already has an optional-dependency adapter for `gunray`.
- **`meanings`** provides the *graph toolbox the library lacks*: SCCs (`graph_analysis.strongly_connected_components`), induced subgraphs (`induced_subgraph`), the leaf-stripping kernel (`compute_kernel`), and three FVS / cycle-hitting heuristics (`minset.py`), plus the spectral layer (`spectral_analysis.py`). **It has no semantics solver of its own** — no grounded/stable/preferred, no SAT encoding.
- **They are complementary.** The OEWN definition digraph is a *relabeling* of `argumentation`'s core object, not a restructuring (per `reports/argumentation-bridge-oewn.md`). The bridge module `src/meanings/argumentation_bridge.py` is the seam: it builds `argumentation` data structures from a `meanings` `Adjacency` and **reuses `meanings.graph_analysis` for all graph work** (the module docstring is explicit: "does not reimplement any graph algorithms"). Two readings:
  - `dung_attack_framework(nodes, adjacency)` (`argumentation_bridge.py:54`) — *attack reading*: `u → v` ⇒ "u attacks v". Self-loops become legal self-attacks. This is the reading under which "grounded extension" is non-trivial.
  - `bipolar_support_framework(nodes, adjacency)` (`:66`) — *support reading*: `u → v` ⇒ "u supports v" ("you can't accept v until you accept its definiens"). `defeats` is empty *by construction* — the attacks a richer model would carry (polysemy, prototype exceptions) are exactly what `paper-wordnet` discards by collapsing to `lemma::pos`.
  - `kernel_attack_framework(analysis, adjacency)` (`:82`) and `scc_attack_framework(scc, adjacency)` (`:88`) restrict the attack-reading AF to the Kernel or one SCC.

  The patched `argumentation` side: `dung.grounded_extension` and `bipolar.bipolar_grounded_extension` were replaced/rewired this round (see §2). New tests `tests/test_argumentation_bridge.py` (chain, 2-cycle, self-loop, support edges).

### 1.3 The deliverable surfaces (current vs target)

- **Current Up-Goer surface:** the `lemma::pos`-graph FVS seed (`KernelAnalysis.seed_nodes`) projected to human words by the kernel-wordlist exporter. Q has been shipping this. `notes/upgoer-identity-clusters.md` is Q's own diagnosis that this raw projection is *not* the final thing — a WordNet lemma is not automatically an English primitive (`no::n` = Nobelium; `s::n` = sulfur/letter; `ax`/`axe` form variants; `color`/`colour` spelling variants; `bless her heart` a construction).
- **Target surfaces (two, per the upgoer note):** (a) a **strict graph seed** — a feedback-vertex result over *typed sense/IC nodes* (formally: the grounded extension restricted to typed-lexical ICs, per §7 of `reports/sibling-tools-connection.md`); (b) a **human Up-Goer vocabulary** — a controlled-vocabulary projection with an *admission policy* (formally: the admitted extension of a defeasible admission theory over typed IC nodes). These are *different objects* — the strict seed is graph-necessity; the human list is human-primitive admission, and the upgoer note's "required invariants" forbid conflating them ("graph necessity is not human primitive admission").

Findings:

Support reading: defeat relation empty ⇒ grounded = the whole 160,010-node argument set (analytic; the library can't even compute it at scale). `seed`/MinSet and the grounded extension are essentially disjoint (overlap 2) — an FVS member is grounded-from-outside, the grounded extension is what the graph forces from inside; no reason to coincide.

Because the giant core and 63 others are UNSAT, **the Kernel AF as a whole has no stable extension** — so the repo's `seed`/MinSet does *not* correspond to "outsiders of a stable extension"; there is no stable extension whose outsider set it could be. No SCC choked z3 — the blockers are library implementation, not the maths.

Q said in the synthesis spec brief this is pinned at **`4a1c31cc`** — *flag: I did not open `pyproject.toml` to confirm the exact hash; treat `4a1c31cc` as the authoritative pin per Q.* `z3-solver` is now a direct dep; `pytest` a dev dep.

## 3. What to build, in priority order

Concrete module/file targets. I rank by *value × readiness*: highest = high value and unblocked today.

### Priority 1 — `meanings.argumentation_dispatch`: the SCC + linear-grounded-on-the-acyclic-part + per-SCC-z3 + FVS-backdoor dispatcher

**This is the build I'd do first.** Everything points at it: `reports/argumentation-bridge-oewn.md` "Next module" §, `reports/sibling-tools-connection.md` "what to do next" #1, and the synthesis spec's prototype-implementation row all name it. It is unblocked — the patched `argumentation` is pinned and merged, `argumentation_bridge.py` exists, z3 handled the 8k core in 3.3 s, the maths is decided.

New module `src/meanings/argumentation_dispatch.py` (+ `scripts/argumentation_dispatch_oewn.py`, `tests/test_argumentation_dispatch.py`, `reports/argumentation-dispatch-oewn.{md,json}`). Algorithm, made concrete by the bridge numbers:

1. **Condense.** `graph_analysis.strongly_connected_components` → condensation DAG. The acyclic part (141,859 Rest nodes + 5,642 plain-singleton Kernel SCCs) gets the linear grounded/preferred labelling directly — no SAT, ~0.8 s. The 2,804 self-loop singletons are trivially OUT-or-UNDEC.
2. **Per-SCC z3 only where it matters.** Each non-singleton SCC (~693, one 8,138-node giant, rest ≤ 11 nodes) → `argumentation_bridge.scc_attack_framework` → `argumentation.af_sat` (stable) / `find_preferred_extension`. **Cache by SCC isomorphism class** — the tiny SCCs are mostly structurally identical (2-cycles, 3-cycles); canonical-form key (sorted-degree-sequence + a graph hash) → cache. Cumulative per-SCC z3 time at this scale: ~4 s.
3. **FVS backdoor for the giant SCC.** The 8,138-node core is the only one where a single SAT call is non-instant (3.3 s) and enumeration explodes. Use `minset.py`'s FVS machinery (`exact_*` / `bounded_cycle_hitting_set` restricted to that SCC) as a **backdoor**: fix the ≤ few-hundred FVS nodes' labels, the residual is acyclic, enumerate over backdoor assignments. (Vincent-Lamarre's MinSet *is* the backdoor — the FVS ⇔ enforcement-set theorem made operational.)
4. **Stitch up the condensation DAG.** Combine per-SCC results bottom-up: grounded is compositional; stable existence = conjunction (any UNSAT SCC ⇒ whole UNSAT, already witnessed); preferred needs a cross-SCC pass.
5. **Replace, don't wrap.** Either upstream a labelling-based `grounded_extension` + SCC-aware dispatcher into `argumentation`, or keep this front-end in `meanings` as "the scale layer the library lacks" and treat the library as the per-SCC oracle. Given the perf fix already upstreamed the linear `grounded_extension`, the *dispatcher* (the SCC front-end + isomorphism cache + FVS backdoor) is the net-new piece and belongs in `meanings` (it depends on `meanings.graph_analysis` and `meanings.minset`, which `argumentation` deliberately lacks).

Deliverable: a report that *re-derives the bridge's numbers via the dispatcher in seconds rather than minutes*, plus the per-SCC stable/preferred map (630 SAT SCCs' extensions; the 63 UNSAT odd-cycle witnesses; the giant-SCC backdoor enumeration result).

### Priority 2 — `argumentation/ranking.py` valuation over the bipolar AF (the non-degenerate replacement for the PageRank attempt)

The spectral pass concluded reverse-PageRank ≈ laundered out-degree, adds essentially nothing over degree (`reports/spectral-valuation-oewn.md`: ρ with out-degree 0.99 full / 0.75 kernel; the FVS heuristic key *is* a degree sum; "incremental-value-over-degree bar not cleared — that's a finding"). `argumentation.ranking` has h-categorizer, burden-based, Potyka, DF-QuAD, Shapley — semantics *designed* to rank arguments by defensibility accounting for attack/support topology, not degree count. New script `scripts/ranking_semantics_oewn.py` (+ `reports/ranking-semantics-oewn.{md,json}`): build the bipolar definition AF via `argumentation_bridge.bipolar_support_framework`, call one or several `ranking` semantics, join with the existing `reports/spectral-valuation-oewn.json` comparison harness (FVS / layers / psycholinguistic norms). ~50–100 lines. Caveat from the connection report: some of these may *also* be O(graph) and degree-dominated on a sparse graph — "another principled score that also collapses to degree" is a publishable negative result too; the comparison *is* the experiment. Lower than P1 because: (a) it may just re-confirm the negative result, (b) it doesn't unblock anything else. *Module location flag:* the connection report says `argumentation/ranking.py` already exists in the library — so this is a *new caller script in `meanings`*, not a new module in `argumentation`; the brief's phrasing "`argumentation/ranking.py` over the bipolar AF" means "use that library module from a meanings script".

### Priority 3 — the `gunray` UNDECIDED demonstrator

~20–30-line script (`scripts/gunray_undecided_demo.py`, + a unit-test-sized test, + a dialectical-tree figure for the paper): a tiny circular definition theory in `gunray`'s `DefeasibleTheory` (`r1: a -< b; r2: b -< a`, no facts) → `UNDECIDED`; add one grounding fact → the chain resolves to `YES`; `render_tree_mermaid` for the figure. This is "recursive definability ≠ meaning" (Harnad's point) mechanized in code, and the cleanest small illustration of the whole grounding thesis. Cheap, unblocked, but it's a *demonstrator* (figure + test), not infrastructure — hence rank 3. Dependency: `gunray` would need to be added to `pyproject.toml` (zero deps, MIT — cheap), or imported via the `argumentation` optional-dependency adapter.

### Priority 4 — the sense-level ingestion rebuild (the big one)

`notes/upgoer-identity-clusters.md` "Next Executable Workstream", expanded by §7 of `reports/sibling-tools-connection.md`. This is the project's biggest open redesign — it turns the argumentation/belief/defeasible connection from a *framing* into the actual *data model*. Steps (with file targets, my naming where the note doesn't):

1. **Ingestion-time lexicality classifier for OEWN senses** — `src/meanings/lexicality.py`: per-sense tag in {lexical word, symbol/code, abbreviation, proper name, taxon, chemical, technical term, phrase, idiom, uncertain}, from gloss text, POS, lexfile, hypernym chain. The "uncertain" tag is first-class (it's the `UNDECIDED` of the admission theory).
2. **Short-token whitelist** — a tiny English short-word list for 1–3-char forms, with tests for `no`, `No`, `s`, `e`, `g`, `ph`, `th`, `ax`, `axe` (the upgoer note names exactly these). The whitelist *admits valid short forms* while the gloss/type check still rejects wrong senses (`no::n` as Nobelium).
3. **IC merge records** — `src/meanings/identity_clusters.py`: high-confidence spelling-variant merges (`color/colour`, `center/centre`, `theater/theatre`, `ax/axe`) as *merge records with per-merge provenance*, **not canonical rewrites** ("we do not rewrite `colour` into `color` and pretend the form disappeared"). Conceptually this is a belief-merge (Konieczny–Pino Pérez) over sense clusters.
4. **Rebuild the paper-wordnet graph with node metadata preserved** — extend `wordnet_pipeline.py` (a new `build_sense_level_graph` or an enriched `build_paper_wordnet_graph`): sense-level nodes carrying lexicality tag + IC membership + dialect/register/domain metadata; definition edges = `supports` between sense nodes (resolve a gloss occurrence to the intended sense, or to the IC, where possible — *this is what dissolves the self-loop artifacts*); attack edges between competing senses of a form; the admission rule a defeasible theory over typed IC nodes.
5. **Export two surfaces** — extend the kernel-wordlist exporter: (a) strict graph seed over typed sense/IC nodes = the grounded extension (via the P1 dispatcher) restricted to typed-lexical ICs; (b) human Up-Goer vocabulary = the admitted extension of the admission theory, with admitted ICs / aliases / exclusions and the merge/exclusion rationale (the dialectical tree is the rationale the admission policy demands).
6. **Measure the delta** — how many current seed artifacts are removed / quarantined / merged without breaking acyclic definitional closure. **Run the falsifiable prediction** (`reports/sibling-tools-connection.md` §7): the lemma-level Kernel *grew* 12,853 → 18,151 with the self-loop fix, pulling in 3,413 gloss self-loops; the upgoer note's diagnosis says many are *artifacts* (a gloss for `violin::n` saying "violin" points at the intended sense / the IC, not a literal self-definition). Prediction: on the sense-level graph many self-loops resolve to a *different* node and dissolve, so the **sense-level Kernel shrinks** relative to the artifact-inflated lemma-level Kernel. If it doesn't shrink, the artifacts were real circularity and the redesign didn't do what it claims — either way it's a check on the redesign.

Why P4 and not P1: it's the biggest in scope, it depends on P1 (step 5 needs the dispatcher's grounded extension), and it collides directly with Q's parallel Up-Goer work (see §4). It's the most important *eventually* — but the right order is dispatcher first, then this on top of it.

### Priority 5 — update the stale Kernel numbers in `swanson-synthesis.md` / `spectral-valuation-oewn.md`

These docs still cite the **pre-self-loop-fix** Kernel: `reports/swanson-synthesis.md:19` "Kernel 12,853; Core 288; Satellites 12,565; combinatorial seed 2,370"; `reports/spectral-valuation-oewn.md:23` "Kernel: 12 853 · kernel SCCs: 3 841 ... 3 148 singletons"; and many derived figures in both (the 2,785-driver-vs-2,370-seed Jaccard in swanson-synthesis; the per-block SCC counts and Spearman tables in spectral-valuation). Post-fix: Kernel 18,151, Core 510, Satellites 17,641, kernel SCCs 9,139 (8,446 singletons of which 2,804 self-loops), seed 3,620 (`bounded-scc`) / 5,044 (`exact-small-greedy`). **Not a blind find-and-replace** — the spectral and Swanson *experiments were run on the 12,853-node Kernel*; the honest fix is either to re-run them on the 18,151-node Kernel (a real rerun, hours of compute via `scripts/spectral_report.py` and the regression scripts) or to add a dated "these numbers predate commit `7d12e64`; the post-fix Kernel is 18,151 — see `reports/self-loop-fix-impact.md`; rerun pending" callout to each. The synthesis itself should carry the post-fix numbers and flag the derived analyses as pending rerun. Cheap if done as a callout; expensive if done as a rerun — recommend the callout now, schedule the rerun.

### Priority 6 — further `../argumentation` perf work: int-indexed adjacency for genuinely sub-second grounded at 160k

The perf fix got grounded from >200 s-and-killed to ~1.5 s at 160k, but the verifier flagged the residual constant factor: `_attackers_index` / `_targets_index` rebuild every `dict[str, frozenset[str]]` adjacency set on every call. To get genuinely sub-second: intern node labels to `int` ids once, use array-indexed adjacency (or `dict[int, set[int]]`) internally, map back at the boundary. This is a *separate change* to `argumentation` (arguably not reusing `_attackers_index` at all) — and it only matters if the "well under a second" target is firm and grounded is being called repeatedly (e.g. inside the P1 dispatcher's per-SCC loop, though there each SCC is tiny). Lowest priority: the current ~1.5 s is fine for the one-pass downstream analysis, and the P1 dispatcher mostly hands work to z3, not to `grounded_extension`. Do this only if profiling the dispatcher shows `grounded_extension` is hot.

Two distinct artifacts, never to be conflated (the upgoer note's invariants make this load-bearing):

Correlation (LLM, embeddings, corpus stats) supplies *arguments* into this theory — adjudicated by the typed rules, never accepted wholesale ("the target artifact is typed, inspectable, falsifiable" — not vector soup). The dialectical tree per admitted/excluded IC *is* the rationale the policy demands.
