## 1. `stable_exists` over-reports UNSAT on context-dependent graphs — and `exact_stable_count` does NOT save it

- **Issue.** `dispatch_stable` picks **one** stable extension for each upstream SCC (greedy: `_brute_force_stable(...)[0]` / `find_stable_extension(...)`), accumulates its IN-set into `all_in`, and uses that single choice to compute the forced-OUT context for downstream SCCs. If a downstream SCC's residual AF is UNSAT under the *greedy* upstream choice but SAT under a *different* upstream stable extension, `stable_exists` returns `False` though the whole AF has a stable extension. Worse: when `overall_exists` is `False`, `dispatch_stable` sets `exact_stable_count = 0` **without running `_exact_stable_count`** (line 533: `if not overall_exists: exact_count = 0`). So the "full DAG DP" path — which *is* implemented correctly and *would* return the right answer — is short-circuited and can never correct a false UNSAT. `stable_witness` also returns `None`, and `credulous_accepts` / `skeptical_accepts` both early-return `False` (`if not res.stable_exists: return False`), so they are wrong too on such graphs.
- **Evidence** (`scratch/test_stable_exists.py`). Graph: upstream 2-cycle `a↔b` (stable exts `{a}` and `{b}`), downstream 3-cycle `x→y→z→x` (UNSAT in isolation), cross-edge `b→x`. Monolithic `argumentation.af_sat.find_stable_extension` on the whole graph (ground truth) returns `frozenset({'b','y'})` — **SAT**. `dispatch_stable.stable_exists` → `False`; `exact_stable_count` → `0`; `stable_witness` → `None`. The greedy sweep picked `{a}` (because `_brute_force_stable` enumerates masks in order, `{a}` before `{b}`), `b` is then OUT, `x` is not forced OUT, the residual 3-cycle is UNSAT → reported UNSAT. Calling `_exact_stable_count(cond, cross_in)` *directly* on the same condensation returns `1` (correct) — confirming the DP is sound and is simply never invoked here. Swapping the cross-edge to `a→x` (so the greedy choice `{a}` *does* force `x` out) makes `dispatch_stable` report `True`/`exact_count=1` — i.e. correctness is luck-of-enumeration-order. Non-context-dependent graphs (bare 3-cycle UNSAT, 4-cycle 2-stable-exts) are handled correctly, and `credulous_accepts`/`skeptical_accepts` agree with hand-computation on those.
- **Severity:** **bug** (silent wrong answer on a well-defined, non-pathological class of inputs) — *plus* an **over-claim** in `reports/synthesis.md` §2/§7: "the exact-count path uses full DAG DP without that issue" is false for the *returned* `exact_stable_count`, which is forced to `0` whenever the greedy says UNSAT. And "(stable_exists) definitive for the OEWN Kernel (its UNSAT SCCs are UNSAT regardless of context)" rests on an assumption the code does not verify and that is *false in general* — forcing a node OUT of an odd cycle makes it SAT (3-cycle minus a node = SAT path), so a downstream odd-cycle SCC that receives a cross-SCC attack edge from an IN-able node *can* be rescued. Whether none of the 63 UNSAT Kernel SCCs can be simultaneously rescued by some consistent global choice is exactly what `_exact_stable_count` would decide — and that path is bypassed. The monolithic z3 run in `reports/argumentation-bridge-oewn.md` confirms the 8,138-node giant core SCC is UNSAT *in isolation* (forced_out = ∅), but isolation is the *least*-constrained context (forcing nodes OUT only removes constraints), so even that does not establish UNSAT-under-upstream-forcing unless the giant SCC is a source SCC of the condensation (not stated anywhere).
- **Fix.** Two options. (a) Cheap+honest: when the greedy sweep returns `False`, do **not** trust it — fall through to `_exact_stable_count` (if all residuals are ≤ `_BRUTE_FORCE_MAX`) or to a monolithic z3 call on the whole AF, and only then report UNSAT; at minimum set `exact_stable_count = None` (not `0`) when the greedy short-circuit fires so callers know it wasn't computed. (b) Correct: replace the single-witness propagation with a proper condensation fixpoint — a downstream SCC is UNSAT-in-context only if it is UNSAT under *every* feasible upstream forced-OUT set; for the boolean that is the `_exact_stable_count > 0` DP (or a z3 encoding of the whole AF). Either way, re-run the OEWN Kernel claim through it before keeping "the Kernel AF is UNSAT" as a *verified* result rather than a *plausible conjecture*.

## 4. The sense-level resolver's 54%-ambiguous-skip is a *systematic* edge-class loss concentrated on the Kernel-forming vocabulary — biasing, not benign conservatism

- **Issue.** `build_sense_level_paper_wordnet_graph` resolves a gloss-token candidate to a sense node only if either (a) the word has exactly **one** sense with the *same POS* as the target (`resolved_same_pos_unique`), or (b) there are several but `choose_best_candidate` finds a **strict** signature-overlap winner (`*_overlap`); otherwise → `ambiguous_skipped`. `choose_best_candidate` returns `None` on zero overlap *and on ties* (lines 96–99). Critically, branch (a) — the dominant resolution path (221,897 of the 423,927 resolved edges) — **cannot fire for a polysemous word by construction**: a word with ≥2 same-POS senses is never `same_pos_unique`. Such a word can enter the graph as an edge *source* only via the overlap tie-break, which the published stats show succeeds for only ~18% of ambiguous cases (86,471 same-POS-overlap + 21,115 global-overlap resolved vs 499,860 skipped).
- **Evidence.**
  - `reports/oewn-sense-ingestion-summary.json` `resolution_stats`: 925,283 candidate matches → 423,927 resolved, **499,860 ambiguous_skipped** (54.0%), 1,496 self-reference, 0 unresolved. Edges/node 418,094 / 212,478 ≈ 1.97 vs lemma-level 4.24 (per `reports/synthesis.md` §3).
  - Sense counts for the canonical high-frequency genus words (`scratch/poly.log`, from `wn` directly): `line` n=30, `point` n=26, `head` n=33, `case` n=20, `run` n=16/v=41, `set` n=12/v=25, `break` v=59, `take` v=42, `make` v=49, `go` v=30, `act` n=5/v=9. Every gloss occurrence of these words faces 12–59 same-POS candidates and is dropped unless the target's gloss tokens happen to overlap one sense's signature strictly more than all others — which is rare for short glosses. So these words' *senses* receive almost no incoming gloss edges.
  - Consequence for the Kernel: a sense node with in-degree 0 is in no cycle, hence not in the FVS/Kernel. Dropping (nearly) all incoming edges to the senses of `set`/`run`/`line`/`point`/`head`/`case`/`take`/`make`/`break` removes exactly the high-out-degree genus words that on the lemma graph form the cyclic core. So the sense-level Kernel (12,142) being smaller than the lemma-level Kernel (18,151) is **partly** "we deleted the edges that would have made those words cyclic," not only "the WordNet first-representative-synset artifacts dissolved."
- **Severity:** **over-claim** (the resolver itself is doing a defensible conservative thing per-edge — "better no edge than a wrong one" — but `reports/synthesis.md` §3/§7's framing understates the bias: it's not random edge loss, it's loss structured to remove the Kernel-forming words; the "12,142 vs 18,151 → artifacts dissolved" comparison is confounded and should not be cited as evidence of artifact dissolution without the edge-budget-controlled comparison agenda #5 already owes). Not a code bug — the resolver behaves as designed.
- **Fix.** No code fix needed for correctness. For the *claim*: (i) the synthesis already hedges this in §3/§7 — strengthen the hedge to "the skip set is concentrated on high-polysemy genus vocabulary, so the Kernel comparison is not apples-to-apples"; (ii) the proper measurement (owed by agenda #5) is an edge-budget-controlled or coverage-controlled comparison — e.g. report the lemma-level Kernel computed after dropping the same fraction of edges, or report the sense-level Kernel under a less conservative resolver (e.g. first-synset fallback, or distributing the edge over all candidate senses); (iii) optionally, when same-POS-overlap ties, fall back to the *most frequent* sense (WordNet sense order) rather than skipping — that recovers a large slice of the genus-word edges with a known, citable bias instead of an invisible one.

## Bottom line

- **Most important finding:** #1 — `stable_exists` (and `exact_stable_count`, `stable_witness`, `credulous_accepts`, `skeptical_accepts`) give silently wrong answers on context-dependent graphs, and the "exact DAG-DP path doesn't have this issue" claim is false *as the value is returned* (it's clamped to 0 whenever the greedy short-circuits). The OEWN-Kernel-UNSAT verdict is therefore a plausible conjecture, not a verified result, from this module.
- **Is `stable_exists` sound on the OEWN Kernel?** **With caveats / unverified.** It will not *under*-report UNSAT, and it returns UNSAT on the Kernel; whether that UNSAT is *correct* depends on the unproven assumption "every UNSAT Kernel SCC stays UNSAT under all upstream forced-OUT contexts," which is false in general (forcing a node out of an odd cycle makes it SAT) and which this code does not check. The independent monolithic z3 run only establishes the giant core SCC is UNSAT *in isolation*, not under upstream forcing. Needs re-running through the corrected path before "the Kernel AF is UNSAT" is a verified claim.
- **Is the 54% skip benign or biasing?** **Biasing.** It is per-edge defensible conservatism, but the skip set is concentrated on exactly the high-polysemy genus vocabulary (`set`/`run`/`line`/`point`/`head`/`case`/`take`/`make`/`break`, 12–59 senses each) that forms the cyclic core, so it pushes the sense-level Kernel down for a reason unrelated to "artifacts dissolved." The 12,142-vs-18,151 comparison should not be cited as evidence of artifact dissolution without an edge-budget-controlled control (already on the agenda as #5).
- **gunray-demo check:** **passes** — the `UNDECIDED → YES` flip happens (9/9), the 9-word slice is a genuine strongly-connected component with gloss-accurate edges, and grounding its 4-node FVS resolves all 9. Only the "smallest cyclic SCC in the `build_lemma_graph` Kernel" provenance is unverified-by-me (no cached `build_lemma_graph`; rebuild doesn't fit budget) — not contradicted.
